# Data

```
data/
├── raw/
│   ├── cobra/                     benchmarks + labels (public release of the CoBRA paper)
│   │   ├── Hariboss_TR60/         HARIBOSS+TR60: *-bindingsite.txt + train/val/test.csv
│   │   ├── TE18/ TL12/ JL10/ RB9/ *-bindingsite.txt  (four independent test sets)
│   │   └── RNABindset/            RBind source release (RB9 derives from RB19)

│   ├── ss_output.tsv              RNAfold MFE dot-bracket per chain
│   └── ss_bp_prob*.tsv            base-pairing probability matrices (secondary-structure

├── processed/                     cached features and graphs (regenerable, not in git)
└── leaked_pairs.json              train/val chains removed by the de-leaking protocol
```

## Label definition

A nucleotide is labelled **binding** if any of its heavy atoms lies within **4 Å** of a ligand
heavy atom; the official per-nucleotide labels of the benchmark release are used unchanged, so
all comparisons against CoBRA / GRASSP / GATRsite are on identical test data.

## Provenance

`data/raw/cobra/` is redistributed here exactly as published with CoBRA, which in turn collects
the benchmarks from their original sources:

| Split | Source | Chains (original → de-leaked) |
|:--|:--|:--|
| train / val | HARIBOSS + TR60 | 345 → 314 train, 43 → 40 val |
| TE18 | RNAsite | 18 |
| TL12, JL10 | ZeSTa | 12, 10 |
| RB9 | RBind (RB19 subset) | 9 → 6 |

Please cite the original dataset papers as well when reusing these files.

## Two corrections applied in this work (part of the protocol)

1. **De-leaking.** 31 training chains and 3 validation chains are byte-identical to test-set
   sequences. They are listed in `leaked_pairs.json` and removed by `--drop_val_leaked`.
   The overlap is inherited from the HARIBOSS training pool (a continuously updated
   PDB-mined database), which is why it is invisible in the RB9-vs-TR60 de-duplication
   performed by the original benchmark construction. Full census:
   `results/homology_audit.json`.
2. **Cross-test-set duplicates.** `1nem_A`, `1q8n_A` and `2tob_A` occur in both TE18 and RB9
   (identical sequences). They are kept in TE18 and dropped from RB9
   (`data_loader.DROP_FROM_SPLIT`), otherwise the four-set average counts them twice.

## Regenerating the secondary structure

`src/ss.py` writes `data/raw/ss_input.fa`; the MFE dot-bracket file is then produced by
ViennaRNA's `RNAfold` (we ran it under WSL because the Windows build of ViennaRNA was not
available in our Python environment):

```bash
python -c "import sys; sys.path.insert(0,'src'); import ss; ss.prepare_input()"
cat data/raw/ss_input.fa | RNAfold --noPS -p0 > data/raw/ss_output.tsv   # (approx.; see src/ss.py)
```

If you have the ViennaRNA Python bindings installed, `src/ss.py` can compute the folds directly.

## Large artefacts

`data/processed/*.pt` (graphs and cached embeddings, ≈2.9 GB in total) are regenerated by
`scripts/01`–`04`. They are excluded from version control; see the main README for how to
obtain the released copies.
